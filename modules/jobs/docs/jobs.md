# Отложенные задания

Панель `/panel/jobs.html` показывает задания `setTimeOut()` и `addScheduledJob()`:
название, PHP-команду, время запуска, число попыток, состояние и последнюю ошибку.
Есть поиск, фильтр состояния, страницы по 50 строк, создание и отмена.
Изменяющие действия требуют POST и CSRF. Старые ссылки открываются, но GET
больше не отменяет задания. Отмена не прерывает команду, уже начавшую выполняться.

## Повторы

По умолчанию доступны три попытки: первоначальная и две повторные.
После первой ошибки задержка составляет 5 секунд, после второй — 10 секунд.
Исключение, `return false;`, результат `['success' => false]`, таймаут и обрыв
исполнителя считаются неуспехом. Успешная команда больше не запускается.
После аварии контроллера аренда восстанавливается через таймаут выполнения
плюс 60 секунд. Действующий старый исполнитель сохраняет владение даже при
потере Redis. Три аварийные попытки также останавливают задание.

Для передачи ошибки вызываемой команды возвращайте её результат:

```php
return cm('KitchenLight.turnOff');
```

Постановка команды в очередь MQTT ещё не подтверждает получение устройством.
Повтор после обрыва может повторить уже выполненную часть PHP-команды;
учитывайте это для операций, которые нельзя выполнить дважды.

Новое задание с прежним названием атомарно заменяет ожидавшее задание.
Результат замены не отменяет побочные действия уже работающего исполнителя.

## Redis и сохранность

SQL-таблица `jobs` сохраняет команду, состояние и аренду. При доступном Redis
сроки находятся в sorted set `scheduler:due`; пустой тик не читает SQL.
Новая команда публикуется после COMMIT. Сверка незавершённой передачи SQL → Redis
происходит раз в 30 секунд; очистка старых записей — раз в минуту.
После потери Redis или вытеснения индекса расписание восстанавливается из SQL.
Без Redis используется прежний SQL-отбор. Redis не является единственным
хранилищем задания.

Завершённые и окончательно ошибочные записи с непустым `EXPIRE` удаляются
через семь дней после этого срока. Задания без срока хранятся до удаления
из панели или замены по имени.

## Цепочка изменений

Миграция `20261025_scheduler_trace` добавляет `TRACE_ID`, `PARENT_EVENT_ID`,
`DISPATCH_GENERATION` и индекс. Постановка, выполнение и повторные попытки
остаются в цепочке создавшего их метода/сценария. Сохраняется снимок кода
каждой попытки. Кнопка маршрута открывает общий drawer «Цепочка изменений»;
он доступен ещё до первого изменения свойства. Последующие методы и свойства
попадают в ту же цепочку. Срок хранения задаёт `PROPERTY_AUDIT_RETENTION_DAYS`.

Задания, созданные до миграции, получают trace при первом выполнении;
восстановить их прежнего создателя невозможно. Удаление панели jobs не удаляет
системную таблицу таймеров.

Диагностика без выполнения: `php majordomo jobs:list --status=failed --json`.
При обновлении нужна штатная миграция и перезапуск `cycle_scheduler`.

- `node tests/jobs_browser_smoke.mjs` — локальная фикстура, CodeMirror,
  drawer, повторный partLoad, светлая/тёмная темы и ширины 1440/390 px.
