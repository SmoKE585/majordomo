# ИИ-помощник — установка и состояние

Модуль работает в существующей админке MajorDoMo. Адрес раздела —
`/panel/ai_assistant.html`. После системного обновления модуль устанавливается
автоматически при первой загрузке панели (запись в реестре, маркер установки и
собственные таблицы), поэтому его карточка появляется в меню сразу. Отдельного
выключателя нет: установленный модуль сразу доступен. Готовность
определяется настройками — нужен включённый провайдер, модель и агент с этой
моделью. Просмотр настроек и базы знаний не обращается к провайдеру; запрос к
модели выполняется только при диалоге или проверке соединения.

## Зависимости

PHP-библиотека `neuron-core/neuron-ai` устанавливается через Composer;
зафиксированная в `composer.lock` версия — 4.1.13. Она требует PHP 8.1+
и расширение cURL. Qdrant подключается как отдельный опциональный сервис.
Для разработки и обновления зависимостей целевая платформа Composer — PHP 8.1.0.

Классы модуля находятся в `modules/ai_assistant/src/` и загружаются Composer
в пространстве `MajorDoMo\Modules\AiAssistant`. Сервисы ядра используются
через существующий API; логика ИИ-помощника остаётся внутри модуля.

## Обновление и доступность

Собственная таблица `ai_assistant_settings` хранит версию схемы и состояние
модуля. Обновление схемы выполняется при загрузке модуля, даже если маркер
установки уже существует. Повторная установка не сбрасывает настройки.
Откат на код, который не понимает более новую схему, завершается ошибкой
и не понижает версию данных.

Старого выключателя `ENABLED` больше нет в интерфейсе и логике. При обновлении
старых установок значение приводится к включённому состоянию; при удалении
модуль снимается с регистрации, а возврат после повторной установки сразу
доступен.

Редактор, действующие методы и сценарии работают и без настроенной модели.
Изменение текста агентом не означает сохранение действующего кода:
его сохраняет пользователь обычной кнопкой редактора.

## Удаление и сохранение данных

Обычное удаление через управление модулями убирает его регистрацию и маркер.
Собственные данные сохраняются для восстановления при повторной установке.
Это намеренное исключение из общего правила удаления таблиц: очистка настроек
и историй требует отдельного явного подтверждения. Сохранившиеся таблицы сами
не выполняют никакого кода.

Технический контракт очистки: `uninstall('DELETE ai_assistant')`.
Любое другое значение отклоняется до изменения состояния и регистрации.
Это внутренний метод модуля, а не отдельный публичный HTTP-маршрут;
пользовательское действие очистки должно дополнительно проверять сессию,
CSRF и подтверждение. Разработка не вызывает этот метод против рабочей БД.
После восстановления сохранённых данных модуль сразу доступен.

## Статус реализации

На 2026-10-23 реализованы: провайдеры и модели с шифрованием токенов,
диагностика соединения, каталог агентов и два стандартных промпта, защищённые
инструменты чтения установки, чат с потоковым ответом и историей, панель ИИ в
редакторе CodeMirror, текстовый поиск знаний, опциональный Qdrant с пошаговой
сборкой индекса и CLI `ai:index`/`ai:rag-check`.

Ограничения: внешний провайдер и реальный Qdrant в автоматических проверках не
вызывались — использовались локальная имитация и FakeAIProvider. Поведение
конкретной модели нужно проверить вручную. Полный план и результаты проверок —
`docs/agents/ai-agents-todo.md`.

## Ключ шифрования токенов

Токены моделей шифруются AES-256-GCM и сохраняются в БД только как шифротекст.
Каждая модель может иметь собственный токен; для локального API токен необязателен.
При редактировании отсутствие поля токена сохраняет прежнее значение,
явно пустое значение очищает его. В списке и карточке модели возвращается
только признак наличия токена.

Ключ читается через `Config` из необязательного секретного `AI_SECRET_KEY`:
это 32 случайных байта в base64. Если он не задан, при первом сохранении
непустого токена автоматически создаётся приватный файл
`var/ai_assistant/secret.key` с правами 0600. Обычный `.env` при этом не меняется.
Ключ не хранится в БД и не передаётся в браузер или провайдеру.

Сохраняйте резервную копию ключа отдельно от БД. После потери или подмены ключа
старые токены нельзя восстановить: потребуется вернуть прежний ключ или
заново задать токены. Ротация ключа требует перешифрования всех сохранённых
секретов, а не простой замены файла. Обычное удаление модуля сохраняет ключ
вместе с данными для восстановления.

## Стандартные агенты

Первая установка создаёт профили «Помощник MajorDoMo» и «Помощник редактора».
Для работы им нужно назначить модель с чатом, а при выбранных инструментах —
также с поддержкой Tools. Профили можно редактировать и копировать для своих
задач. Доступные инструменты выбираются из фиксированного серверного списка;
текст промпта сам по себе не даёт дополнительных разрешений.

Повторная установка и обновление стандартных инструкций не заменяют
пользовательский текст. Восстановление стандартного промпта — отдельное
действие, сохраняющее выбранную модель. Конкурентное сохранение устаревшей
формы отклоняется, чтобы не затереть более новые изменения.
Удалённый агент исключается из выбора; запись сохраняется для будущей истории
диалогов, а ссылка на модель освобождается. Удалённые стандартные профили
автоматически не восстанавливаются.

## Опциональный Qdrant и модели эмбеддингов

Qdrant не входит в обязательную поставку. Его можно установить отдельно или
подключить на другом сервере. Проверяется доступность настроенного HTTP API,
а не наличие программы на сервере MajorDoMo. Диагностика читает только список
коллекций по [официальному API Qdrant](https://api.qdrant.tech/api-reference/collections/get-collections)
и не передаёт документы. URL, необязательный API-ключ и таймаут хранятся в
настройках модуля; ключ шифруется тем же способом, что токены моделей.
При смене адреса необходимо повторно задать ключ или явно очистить его.

Одна форма «Qdrant и индекс знаний» сохраняет подключение, модель, параметры
коллекции и разбиения. Для `text-embedding-3-large` предустановка: размерность `3072`,
метрика `Cosine`, HNSW `m=16`, `ef_construct=100`; кнопка «Параметры OpenAI Large»
подставляет их. Коллекция создаётся автоматически при индексации, отдельных
«инстансов» Qdrant не требуется. Кнопка «Индексировать базу» появляется в
карточке «Индексы» после сохранения модели.

Режим знаний агента — `text` (обычный поиск) или `rag`. Для RAG нужны выбранные
источники, инструмент поиска знаний, доступный Qdrant и включённая модель с
возможностью «эмбеддинги» у включённого провайдера. При отсутствии любого
условия сервер запрещает создание и копирование RAG-агента и выдаёт подсказку.
Стандартные агенты используют `text`, поэтому их можно настраивать без Qdrant.
После сбоя сервиса режим RAG не подменяется текстовым поиском скрытно.
Агента можно явно перевести обратно в `text` даже при недоступном Qdrant.

У моделей эмбеддингов есть порядок: меньшее значение `EMBEDDING_PRIORITY`
используется первым, при равенстве — меньший ID. Выключенные модели и провайдеры
исключаются из списка. Порядок задаётся в карточке модели; в настройках знаний
выбирается рабочая модель. Для каждой модели создаётся отдельная коллекция:
векторы разных моделей несовместимы даже при одинаковой размерности.

Сборка индекса выполняется по шагам из раздела «База знаний» или командой
`php majordomo ai:index`. Новый индекс пишется в staging-коллекцию и
переключается только после успеха; при ошибке или отмене рабочий индекс
сохраняется. Повторная сборка заменяет индекс целиком, поэтому дублей и
удалённых документов не остаётся.

Команда `php majordomo ai:rag-check --json` проверяет Qdrant и наличие модели.
Она не устанавливает модуль и не создаёт коллекции. Код завершения 0 означает,
что сервис доступен и подходящая модель настроена; 1 — ошибка или отсутствие
настройки. Готовность индекса проверяется отдельно в разделе «База знаний».
Автоматического обращения к Qdrant при просмотре состояния модуля нет.
