# База знаний и Qdrant

Источник знаний — существующие Markdown-файлы: `docs/**/*.md` и документация
установленных модулей. Отдельной копии документов модуль не создаёт.

## Два режима

- **Текстовый поиск** — всегда доступен, не требует внешних сервисов. Ищет по
  заголовкам, описанию и тексту статей.
- **RAG** — смысловой поиск по индексу Qdrant. Нужны доступный Qdrant,
  включённая модель эмбеддингов и собранный индекс.

Режим выбирается у агента. Если Qdrant недоступен, RAG-агент не запускается;
текстовый поиск при этом продолжает работать. Скрытой подмены одного режима
другим нет.

## Подключение Qdrant

Qdrant не входит в стандартную поставку. Установите его отдельно или подключите
на другом сервере. В разделе «База знаний» одна форма сохраняет сразу всё:

- адрес HTTP API (например, `http://127.0.0.1:6333`);
- API-ключ, если сервер его требует;
- таймаут;
- модель эмбеддингов;
- параметры коллекции и разбиения.

Кнопка проверки читает только список коллекций. Документы при диагностике не
передаются. **Отдельных «инстансов» у Qdrant нет**: это один сервис, а коллекция
создаётся автоматически при первой индексации. Ничего вручную в Qdrant создавать
не нужно.

## Модель эмбеддингов

Создайте модель с возможностью «Эмбеддинги» и отметьте её в параметрах индекса.
Можно настроить порядок: меньшее значение приоритета используется раньше.
Выключенные модели и провайдеры исключаются.

Векторы разных моделей несовместимы. Для каждой модели — своя коллекция и своя
размерность; смешивать их в одном индексе нельзя.

### Параметры коллекции

- **Имя вектора** — пусто означает стандартный безымянный вектор Qdrant. Имя
  нужно только для нескольких векторов в одной коллекции.
- **Размерность** — `0` определяет автоматически по ответу модели. Для
  `text-embedding-3-large` — `3072`, для `text-embedding-3-small` — `1536`.
- **Метрика** — для OpenAI-эмбеддингов `Cosine`; также доступны `Dot`, `Euclid`
  и `Manhattan`.
- **HNSW m** — число связей на узел, стандарт Qdrant `16`.
- **HNSW ef_construct** — глубина построения, стандарт `100`.

Кнопка «Параметры OpenAI Large» подставляет `3072`, `Cosine`, `16` и `100`.
Эти значения предназначены для `text-embedding-3-large`; для другой модели
проверьте размерность или укажите `0`.

## Сборка индекса

1. Сохраните форму «Qdrant и индекс знаний» одной кнопкой.
2. Нажмите «Индексировать базу» в карточке «Индексы» (или «Собрать» у строки
   индекса).
3. Дождитесь завершения. Прогресс показывается в карточке.

Сборка идёт порциями из админки. Новый индекс пишется в отдельную коллекцию;
рабочий переключается только после успешного завершения. Если сборка
прервалась, старый индекс продолжает обслуживать поиск.

Изменение модели эмбеддингов или параметров вектора требует полной сборки.
Изменение текста, заголовка, состава справки или разбиения обрабатывается
по отдельным файлам; остальные эмбеддинги не пересчитываются.

## CLI

```bash
php majordomo ai:index --model=1
php majordomo ai:index --all --json
php majordomo ai:index --model=1 --sync --json
php majordomo ai:rag-check --json
```

`ai:index` собирает индекс по шагам и не раскрывает токены. `ai:rag-check`
проверяет доступность Qdrant и наличие модели эмбеддингов, но не создаёт
коллекции и не проверяет актуальность индекса.

## Ограничения

- Для общей установки Qdrant точки разделяются ключом установки, а поиск
  фильтруется по источнику (`core`/`modules`).
- Удаление рабочего индекса заблокировано: сначала соберите новый.
- Автоматические тесты используют имитацию Qdrant; реальный сервис нужно
  проверить отдельно.
- При недоступном Qdrant показывается причина, а не «успешный» пустой ответ.

## Автоматическая сверка файлов

После установки модулей, обновления системы и сохранения настроек Qdrant
проверка ставится на штатный именованный таймер через 30 секунд. Серия событий
объединяется; дополнительно сверка запускается каждый час. Нужны подключённый
Qdrant и выбранная включённая модель эмбеддингов. При отсутствии индекса
первоначальная сборка идёт порциями в фоне.

Для готовой коллекции читаются метаданные фрагментов: ID документа, контрольная
сумма и количество. Поэтому обнаруживаются не только изменённые файлы, но и
точки, потерянные в Qdrant. Новая редакция файла сначала записывается целиком,
затем удаляется прежняя. Удалённая справка убирается по фильтру документа и
ключу установки. Ошибка сохраняется у индекса, прежние фрагменты не удаляются
до успешной записи новых; предусмотрены до двух автоматических повторов.

Контракты Qdrant: [чтение метаданных страницами](https://api.qdrant.tech/api-reference/points/scroll-points)
и [удаление по фильтру](https://api.qdrant.tech/api-reference/points/delete-points).
