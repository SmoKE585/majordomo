Как работает модуль

Подключение роутеров, устройства и привязки, обработчики, подключения, DNS и API.

KeeneticOS 2.13+ REST API /rci Обработчики на PHP
К роутерам Тема на форуме

Модуль работает с интернет-центрами Keenetic с прошивкой не ниже 2.13 через REST API /rci. Команды можно проверять в веб-интерфейсе роутера по адресу http://IP_роутера/a.

Возможности:

  • несколько роутеров, IP-адрес или KeenDNS-имя;
  • доступность роутера и наличие интернета;
  • активный канал (основной или резервный) и внешний IP;
  • устройства: статус, тип подключения, MAC, IP, трафик, Wi-Fi и RSSI;
  • привязка устройств и подключений к свойствам и методам объектов;
  • отслеживание параметров устройства через класс роутера;
  • PHP-обработчики на смену статуса устройства, подключения и интернета;
  • обновление прошивки, перезагрузка и сохранение конфигурации из интерфейса;
  • управление подключениями и статическими DNS-записями.

Нажмите «Добавить роутер» и заполните:

  • Название — оно же имя класса объектов; после сохранения не меняется;
  • Адрес — IP-адрес, KeenDNS-имя или адрес с портом;
  • Логин и пароль администратора роутера;
  • Период опроса в секундах (по умолчанию 5, 0 — не опрашивать);
  • Перезагрузка без интернета — через сколько секунд перезагрузить роутер при потере связи (0 — не перезагружать).

Модуль сразу авторизуется на роутере, определит модель, прошивку, серийный номер и наличие Wi-Fi-системы (MWS). Если авторизация не прошла, роутер не сохраняется.

Пароль хранится в базе в обратимом зашифрованном виде: Keenetic требует исходный пароль для вычисления ответа на challenge. При редактировании оставьте поле пустым, чтобы не менять сохранённый пароль.

Карточка роутера состоит из вкладок:

  • Обзор — доступность, интернет, внешний IP, прошивка, сводка по устройствам и подключениям, журнал интернет-соединения;
  • Настройки — адрес, логин, пароль, период опроса, автоперезагрузка и отключение проверки прошивки;
  • Устройства — список устройств роутера с поиском, фильтрами и привязками;
  • Подключения — VPN/PPPoE/интерфейсы с тумблерами и обработчиком;
  • DNS — статические записи локальной сети.

В меню «Действия» доступны обновление данных, сохранение конфигурации, установка прошивки, перезагрузка и удаление роутера.

При удалении роутера удаляются его устройства, подключения, привязки и класс объектов с именем роутера.

Список устройств обновляется циклом. Для каждого устройства доступны:

  • имя, MAC, IP, тип подключения (LAN/Wi-Fi), регистрация на роутере;
  • привязка к объекту: свойство (1 — в сети, 0 — не в сети) и метод (вызывается при смене статуса);
  • отслеживание параметров, скрипт на смену статуса и журнал последних событий;
  • Wake-on-LAN для выключенного устройства и регистрация на роутере.

Привязка редактируется в карточке устройства. При сохранении имя устройства синхронизируется с роутером, а статус сразу записывается в привязанное свойство.

Раздел «Все устройства» показывает устройства со всех роутеров, с фильтром по роутеру, статусу, типу и отслеживанию.

При установке модуль создаёт класс Keenetic со свойствами и методом track. При добавлении роутера создаётся подкласс с его именем.

При включении отслеживания в классе роутера создаётся объект с именем устройства, а на каждом опросе вызывается метод track с параметрами:

  • UPTIME — время в сети, сек;
  • RXBYTES, TXBYTES — трафик;
  • ROUTER — точка доступа или роутер;
  • NET — SSID, FREQ — 2.4/5 ГГц;
  • WIFI_MODE — стандарт, MIMO, частота и скорость;
  • RSSI — уровень сигнала.

Стандартный метод раскладывает параметры по свойствам. Его можно заменить своим методом объекта — это сократит количество записей в базу.

При включённом отслеживании каждый опрос записывает до 8 свойств на устройство. Включайте его только для нужных устройств.

Скрипт устройства выполняется при смене статуса. Доступны $status (1 — в сети), $device (данные роутера) и $router.

if ($status) { // устройство появилось в сети
    $text = 'в сети';
} else { // устройство отключилось
    $text = 'не в сети';
}
say('Телефон ребёнка ' . $text, 1);

if ($status && !empty($device['ip'])) {
    say('IP: ' . $device['ip'], 1);
}

Скрипт подключения получает $name, $state, $connection и $router:

if ($state) {
    say('Соединение ' . $name . ' установлено', 2);
} else {
    say('Соединение ' . $name . ' потеряно', 2);
}

Скрипт «Интернета» получает $status: 0 — интернета нет, 1 — основной канал, 2 и выше — резервный канал (номер канала = $status - 1), а также $inet и $router.

Код проверяется на синтаксис перед сохранением. Ошибки выполнения пишутся в системные ошибки MajorDoMo с контекстом.

Вкладка «Подключения» показывает интерфейсы, которые роутер отдаёт в show interface: VPN, PPPoE и другие. Служебные интерфейсы (Bridge, WifiMaster, GigabitEthernet и т. п.) скрыты.

Тумблер включает и выключает подключение сразу, без сохранения формы. Через привязанное свойство подключением тоже можно управлять: запись 1 включает, 0 выключает.

Обработчик выполняется при смене фактического состояния подключения. Конфигурация на роутере сохраняется автоматически.

Вкладка «DNS» управляет статическими записями ip host в конфигурации роутера. Укажите доменное имя и IPv4-адрес — модуль добавит запись и сохранит конфигурацию.

Работает только внутри локальной сети. Список читается из show running-config.

Произвольная команда RCI:

include_once(DIR_MODULES . 'keenetic/keenetic.class.php');
$keenetic = new keenetic();
$result = $keenetic->command('1', '{"show": {"ip": {"hotspot": {}}}}', true);

Первый параметр — ID роутера или его адрес. Третий параметр — сохранить конфигурацию на роутере.

Перезагрузка и Wake-on-LAN:

$keenetic->reboot('1');
$keenetic->wol('68:72:c3:56:42:81');

Управление подключением: $keenetic->changeConnection('id или название', $state), где $state — 0 выключить, 1 включить, 2 переключить.

Через API MajorDoMo:

callAPI('/api/module/keenetic', 'GET', array(
    'id' => 1,
    'path' => 'show/interface',
    'data' => ''
));

Параметр id — ID роутера или его адрес. Ответ возвращается массивом, ошибки — false.

  • Роутер недоступен. Проверьте адрес и доступность веб-интерфейса. Локальный IP открывается по HTTP, KeenDNS — по HTTPS.
  • Ошибка авторизации. Проверьте логин и пароль. Если пароль менялся, введите его заново в настройках роутера.
  • Нет устройств. Проверьте период опроса (не 0), состояние цикла и журнал интернета. Пустой ответ роутера не удаляет устройства.
  • Не приходят уведомления о прошивке. Проверьте «Проверять обновления» в настройках модуля и «Не проверять обновления» у конкретного роутера.
  • Нужны подробности. Включите «Отладка DebMes» в настройках модуля и смотрите YYYY-mm-dd_keenetic.log в каталоге логов.

Если статус устройства «мигает», включите для него отслеживание или увеличьте период опроса: проводные устройства иногда пропадают из агрегированного списка на один опрос.
