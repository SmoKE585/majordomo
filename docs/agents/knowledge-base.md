# База знаний в админке

## Коротко

Раздел `/panel/knowledge_base.html` читает те же Markdown-файлы, что и агенты: `docs/**/*.md` и `modules/<name>/docs/**` установленных модулей. Отдельной таблицы в БД нет; категория, аудитория и порядок задаются во front matter, а новый файл появляется в списке на следующем запросе. Пользовательские материалы помечайте `audience: user`, технические — `agent`.

Раздел **«База знаний»** (`/panel/knowledge_base.html`) показывает содержимое каталога `docs/` прямо в админке. Отдельной базы данных и второй копии текстов нет: источник истины — те же Markdown-файлы, которые читают агенты.

## 1. Что попадёт в раздел

В раздел попадают все файлы `docs/**/*.md` и документация **установленных** модулей:

| Источник | Что сканируется | Идентификатор | URL |
| --- | --- | --- | --- |
| Ядро | `docs/**/*.md` | путь без `.md` | `/panel/knowledge_base/<path>.html` |
| Модуль | `modules/<name>/docs/**/*.md` | `module/<name>/<path>` | `/panel/knowledge_base/module/<name>/<path>.html` |
| Модуль без `docs/` | `modules/<name>/README.md` | `module/<name>/README` | `/panel/knowledge_base/module/<name>/README.html` |

Служебные каталоги и картинки игнорируются. Новый файл появляется в списке на следующем запросе, пересобирать ничего не нужно.

Документация модуля видна **только пока модуль установлен** (`cms/modules_installed/<name>.installed`). После удаления модуля его материалы исчезают из раздела автоматически. Это позволяет каждому модулю поставлять собственную инструкцию рядом с кодом, не дублируя её в `docs/`.

Путь файла одновременно является идентификатором материала:

| Файл | Идентификатор | URL в админке |
| --- | --- | --- |
| `docs/README.md` | `README` | `/panel/knowledge_base/README.html` |
| `docs/user/commands.md` | `user/commands` | `/panel/knowledge_base/user/commands.html` |
| `docs/agents/AGENTS.md` | `agents/AGENTS` | `/panel/knowledge_base/agents/AGENTS.html` |
| `modules/yandexhome/docs/setup.md` | `module/yandexhome/setup` | `/panel/knowledge_base/module/yandexhome/setup.html` |

## 2. Метки и аудитория

Аудитория задаётся во front matter. Без него работает правило по каталогу:

| Каталог | Аудитория по умолчанию |
| --- | --- |
| `docs/user/**` | пользователь |
| `docs/agents/**` | агент |
| `docs/deploy/**` | агент |
| `docs/dev/**` | агент |
| `docs/archive/**` | агент |
| `docs/*.md` | пользователь и агент |
| `modules/<name>/**` | пользователь и агент |
| другие каталоги `docs/**` | агент |

Пример front matter:

```markdown
---
title: Доступные команды
audience: user, agent
category: user
tags: команды, cli, установка
description: Короткое описание для карточки в списке.
---

# Доступные команды

Текст инструкции.
```

Поддерживаемые ключи:

| Ключ | Значение |
| --- | --- |
| `title` | Заголовок материала. Если не задан — первый `#` в файле. |
| `description` | Описание для карточки. Если не задано — первый абзац. |
| `audience` | `user`, `agent` или `user, agent`. |
| `category` | Ключ категории. По умолчанию — первый каталог внутри `docs/`. |
| `category_label` | Человеческое название категории. |
| `category_icon` | Иконка Tabler без `ti-`. |
| `category_order` | Порядок категории в списке. |
| `tags` | Метки через запятую; участвуют в поиске. |
| `order` | Порядок материала внутри категории (меньше — выше). |
| `icon` | Иконка карточки Tabler без `ti-`. |

Стандартные категории: `general`, `user`, `agents`, `ui` («Интерфейс», иконка `layout-dashboard`, порядок 50), `deploy`, `dev`, `archive`. Метаданные категории `ui` заданы в `docs/agents/DESIGN_SYSTEM.md`; для новой категории достаточно указать её ключ и, при желании, `category_label`/`category_icon` в одном из файлов.

Документы модулей по умолчанию попадают в отдельную категорию `module-<name>` с названием модуля и иконкой `package`. Название можно переопределить во front matter:

```markdown
---
title: Настройка Yandex Home
category_label: Yandex Home
category_icon: home-bolt
order: 10
---
```

### Заметки TODO

Категория `todo` («TODO», иконка `list-check`, порядок 15) предназначена для
обсуждений и требований, которые позднее берутся отдельными задачами
в реализацию. Заметки хранятся в `docs/todo/`, имеют аудиторию `user, agent`
и статус. Одна тема — один файл; правила и список материалов находятся
в [TODO](../todo/README.md). Наличие заметки не означает, что описанная
функция уже реализована или поручена к разработке.

## 3. Разметка

Рендерер поддерживает безопасное подмножество GitHub-flavoured Markdown:

- заголовки, абзацы, списки (вложенные, нумерованные, чек-листы);
- блоки кода (тройные обратные кавычки) и отступы в 4 пробела;
- таблицы, цитаты, горизонтальные линии;
- инлайн-код, **жирный**, *курсив*, ~~зачёркнутый~~;
- ссылки, картинки и `<https://...>`.

Сырой HTML не исполняется — он экранируется. Это осознанное ограничение: документация не должна уметь запускать скрипты в админке.

Ссылки на другие `.md`-файлы автоматически превращаются в ссылки базы знаний. Ссылки на каталоги `user/`, `agents/`, `deploy/`, `dev/`, `archive/` открывают соответствующую категорию. Относительные картинки и файлы переписываются на `/docs/...`.

## 4. Устройство кода

| Файл | Назначение |
| --- | --- |
| `lib/knowledge_base.php` | Реестр документов, front matter, категории, аудитория, поиск, источники установленных модулей. |
| `lib/markdown.php` | Безопасный рендерер Markdown. |
| `modules/knowledge_base/knowledge_base.class.php` | Модуль админки, данные для шаблонов. |
| `templates/knowledge_base/` | Список, статья и состояние «не найдено». |
| `public/assets/modules/knowledge_base/` | Page-only CSS/JS (не входят в общий бандл). |

Модуль не создаёт таблиц. Он регистрируется в `project_modules` стандартным механизмом `checkInstalled()`; `panel.class.php` один раз устанавливает его на существующих инсталляциях, чтобы раздел сразу появился в меню. Если раздел всё же не появился, откройте `/panel/knowledge_base.html` один раз.

## 5. Правила

- Не дублируйте текст инструкции в шаблоне: пишите Markdown в `docs/`.
- Документацию конкретного модуля держите в `modules/<name>/docs/` — она появится в базе знаний только у установленного модуля. Не копируйте её в `docs/`.
- Для пользовательских инструкций используйте `audience: user`, для технических — `agent`.
- Не добавляйте сырой HTML и `<script>`: рендерер всё экранирует.
- Не подключайте сторонние библиотеки для разметки: используется собственный безопасный рендерер.
- Если добавляете новую категорию, задайте ей понятное название и иконку Tabler.
- После изменения `docs/` проверьте страницу `/panel/knowledge_base.html` в светлой и тёмной темах, а также на ширине 390 px.
