# Первичная настройка (setup wizard)

Страница первого запуска: `public/install.php`. Пока мастер не завершён,
админка, сайт, API и прямые object-эндпоинты не открываются — пользователь
попадает на мастер.

## 1. Зачем это нужно

До появления мастера первичная настройка требовала вручную править `.env` и
искать нужные настройки в админке. Новая страница:

- проверяет PHP, расширения, права на файлы и доступность MySQL/MariaDB;
- даёт заполнить `.env` через форму (БД, адрес, часовой пояс, Redis,
  WebSockets, журналы, внешний доступ, интеграции);
- записывает настройки интерфейса в таблицу `settings` (`THEME`,
  `GENERAL_ALICE_NAME`, `SITE_LANGUAGE`, `SITE_TIMEZONE` и т. д.);
- создаёт администратора, если в базе его ещё нет;
- делает резервную копию `.env` и ставит маркер завершённой установки.

После завершения те же параметры доступны в админке: **«Общие настройки»**
(`/panel/settings.html`). Там можно сменить базу, поправить `.env` и
DB-настройки; после сохранения циклы перезапускаются. Подробно —
[`settings.md`](settings.md), управление циклами — [`cycles.md`](cycles.md).

## 2. Как это устроено

```
public/install.php
  └─ MajorDoMo\Core\InstallApplication
       ├─ bootConfiguration()          только config.php, без legacy loader
       ├─ InstallGate / InstallState   состояние установки (файл-маркер)
       ├─ Installer                    валидация, запись, создание admin
       │    ├─ InstallSchema           декларативная схема полей и шагов
       │    ├─ InstallEnvironment      read-only проверки окружения
       │    ├─ InstallDatabase         mysqli без legacy-слоя
       │    ├─ EnvFile                 аккуратная запись .env
       │    └─ InstallFormRenderer     поля через MDJUI
       ├─ templates/install/install.php
       └─ public/assets/install/install.css + install.js
```

`install.php` не подключает `lib/loader.php` и `load_settings.php`: база может
быть недоступна или ещё не содержать таблиц, а мастер обязан показать понятную
ошибку вместо белого экрана.

## 3. Маркер установки и редирект

Маркер: `cms/modules_installed/install.installed` (JSON).

- `status=complete` — мастер завершён, gate пропускает запросы;
- `status=incomplete` — мастер принудительно открыт заново (`reset`);
- файла нет — считается завершённой только старая установка с
  `cms/modules_installed/control_modules.installed` (обратная совместимость).

`InstallGate::redirectIfRequired()` вызывается в:

- `lib/core/AdminApplication.php` — все страницы `/panel/...` и `admin.php`;
- `lib/core/SiteApplication.php` — сайт;
- `public/api.php` — API (JSON 503 с `install_url`);
- `objects/index.php` — прямые object-эндпоинты;
- `lib/loader.php` — дополнительные прямые веб-эндпоинты `modules/*.js.php`,
  `scripts/*` и подобные, которые подключают загрузчик без `Application`.

Обычный браузер получает `302` на `/install.php`, AJAX/API — `503` и JSON:

```json
{"ok":false,"error":"install_required","install_url":"/install.php"}
```

CLI-запуски (`php-fpm`/CLI-скрипты) gate не трогает.

## 4. Что настраивается

| Источник | Примеры |
| --- | --- |
| `.env` | `DB_*`, `PROJECT_TITLE`, `BASE_URL`, `ROOTHTML`, `TIMEZONE`, `APP_ENV`, `DEBUG_MODE`, `GIT_URL`, `REDIS_*`, `WEBSOCKETS_*`, `LOG_*`, `HOME_NETWORK`, `PATH_TO_*` |
| `settings` | `GENERAL_ALICE_NAME`, `SITE_LANGUAGE`, `SITE_TIMEZONE`, `THEME`, `VOICE_LANGUAGE`, `SPEAK_SIGNAL`, `SYSTEM_DB_*`, `ERRORS_KEEP_HISTORY`, `SYSTEM_DISABLE_DEBMES`, `BACKUP_PATH` |
| только UI | `redis_enabled`, `websockets_enabled` — переключатели, которые превращаются в `USE_REDIS` / `DISABLE_WEBSOCKETS` |

Секреты (`DB_PASSWORD`, `REDIS_PASSWORD`, `WEBSOCKETS_AUTH_TOKEN` и т. п.) не
выводятся в HTML. Если значение уже есть,
поле показывается пустым с подсказкой «сохранён»; пустое значение означает
«оставить как есть», а для очистки есть отдельная галочка.

## 5. Запись и безопасность

- `EnvFile` обновляет активные строки на месте, раскомментирует документированные
  ключи из `.env.example`, а новые ключи добавляет в управляемый блок в конце.
- Перед записью создаётся `.env.bak.YYYYmmdd-HHMMSS` (0600).
- Значения с пробелами, `#`, кавычками и `$` записываются в двойных кавычках и
  корректно читаются `Env::parse()`.
- Если ключ перекрыт в `.env.local`, переменной окружения процесса или старой
  константой `config.php`, мастер предупреждает: запись в `.env` не изменит
  эффективное значение.
- Форма защищена CSRF-токеном в сессии (`md_install`), ответы `test_db`
  проверяют тот же токен.
- После записи `.env` очищается `cms/cached/config.php`, чтобы следующий запрос
  прочитал новые значения.
- Мастер не создаёт и не удаляет саму базу данных, но умеет импортировать
  структуру в **пустую** базу. Без обязательных таблиц (`settings`, `users`)
  финальное сохранение блокируется с понятным сообщением.

### Чистая схема для новой установки

Файл — `lib/core/Install/schema.sql`. Это только `CREATE TABLE`/`ALTER TABLE`
из `docs/dev/db_terminal.sql`, без единого `INSERT`: без демо-объектов, старых
свойств, сценариев, настроек и пользователей. Счётчики `AUTO_INCREMENT` из
демо-дампа сброшены.

Импорт выполняется только если база полностью пустая (в `SHOW TABLES` нет ни
одной таблицы) и включён переключатель «Создать таблицы автоматически» на шаге
«База данных». Если в базе уже есть таблицы, автоматический импорт не
выполняется — нужно создать отдельную пустую БД или импортировать схему вручную.
После импорта мастер пишет настройки и создаёт администратора.

При изменении структуры таблиц обновляйте `schema.sql` тем же коммитом, что и
`docs/dev/db_terminal.sql`: в установочном файле должны остаться только
`CREATE TABLE`/`ALTER TABLE` без `INSERT` и без демо-счётчиков
`AUTO_INCREMENT=N`.

## 6. Администратор

Если в базе нет ни одного администратора, третий шаг показывает форму создания:

- логин 3–64 символа (латиница, цифры, точка, дефис, подчёркивание);
- пароль не короче 8 символов;
- создаётся запись `users` (sha512) с `IS_ADMIN=1` — это будущая основа
  авторизации; отдельная таблица `admin_users` больше не используется.

Если администратор уже есть, шаг его не трогает.

Панель больше не показывает форму входа: доступ закрывает reverse proxy
(nginx basic auth), а новая авторизация будет построена на модуле
«Пользователи» и таблице `users`. Старый `control_access`, `admin_users` и
встроенная проверка Basic Auth удалены.

## 7. CLI

```bash
php tools/install.php status     # состояние маркера и URL мастера
php tools/install.php check      # диагностика окружения
php tools/install.php test-db    # проверка БД из .env
php tools/install.php reset      # снова открыть мастер
php tools/install.php complete   # отметить установку завершённой вручную
```

`reset` не удаляет данные и не меняет базу — только переключает маркер.

## 8. URL и nginx

Канонический адрес — `/install.php`: он работает без переписываний и остаётся
доступным, даже если nginx-конфиг устарел. Для удобства в
`docs/deploy/nginx.conf.sample` добавлены `location = /install` и
`location = /install/` → `302 /install.php`. `dev_server.php` умеет оба URL и не
проверяет базу перед отдачей мастера.

## 9. Проверка

```bash
php -l lib/core/InstallApplication.php
php -l lib/core/Install/*.php
node --check public/assets/install/install.js
php tests/install_smoke.php
```

Дополнительно вручную:

- `/panel/` до завершения мастера → `302 /install.php`;
- `/install.php` → 200, шаги переключаются, тема переключается;
- «Проверить подключение» на шаге БД возвращает JSON без записи;
- после завершения `/install.php` → `302 /panel/`, а `/install.php?done=1`
  показывает экран успеха;
- `/panel/` после завершения открывается без формы входа (доступ закрывает
  reverse proxy); созданный пользователь есть в `users` с `IS_ADMIN=1`;
- `/api/` до завершения → `503` JSON.

## 10. Ограничения

- Мастер не создаёт саму базу данных: он только импортирует таблицы в уже
  созданную пустую БД. На базе с таблицами автоматический импорт отключён.
- Восстановление пароля администратора не входит в мастер; пароль сохраняется
  для будущей авторизации на модуле «Пользователи».
- Пока установка не завершена, страница мастера доступна без авторизации; это
  нормально для first-run, но после завершения её нужно закрыть (gate закрывает
  автоматически). Не оставляйте маркер `incomplete` на боевой системе.
