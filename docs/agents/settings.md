# Общие настройки в админке

Страница: `/panel/settings.html` (модуль `settings`). После первичной установки
все параметры мастера доступны здесь же; отдельно открывать `/install.php` для
изменения базы или WebSocket больше не нужно.

## 1. Что где лежит

| Источник | Примеры | Куда пишется |
| --- | --- | --- |
| `.env` | `DB_*`, `PROJECT_TITLE`, `BASE_URL`, `APP_ENV`, `TIMEZONE`, `REDIS_*`, `WEBSOCKETS_*`, `LOG_*`, `HOME_NETWORK`, `PATH_TO_*` | `EnvFile` (с резервной копией `.env.bak.*`) |
| `settings` | `GENERAL_ALICE_NAME`, `SITE_LANGUAGE`, `SITE_TIMEZONE`, `THEME`, `VOICE_LANGUAGE`, `SPEAK_SIGNAL`, `SYSTEM_DB_*`, `ERRORS_KEEP_HISTORY`, `BACKUP_PATH`, `SYSTEM_DEBMES_PATH`, `SYSTEM_WEBSOCKETS_TOKEN` | `InstallDatabase::upsertSettings()` |
| только UI | `redis_enabled`, `websockets_enabled` | превращаются в `USE_REDIS` / `DISABLE_WEBSOCKETS` |

Схема полей — `lib/core/Settings/SettingsSchema.php`. Она **не дублирует**
мастер: берёт `InstallSchema::fields()` и добавляет только те старые
DB-настройки, которых в мастере нет. Поэтому новая настройка первого запуска
автоматически появляется и в админке.

Разделы:

- «Основные» — название, адрес, язык, тема, озвучка, обновления, бэкапы;
- «База данных» — подключение и смена базы;
- «Производительность», «Журналы», «Redis», «WebSockets», «Доступ»,
  «Интеграции»;
- legacy-разделы «Голос: хуки», «События и хуки», «Редактор кода», «Почта» —
  они не входят в мастер и сохранены без изменений.

## 2. Смена базы на лету

1. Открыть «Общие настройки» → «База данных».
2. Указать host/port/name/user/password.
3. Сохранить.

Перед записью `SettingsManager`:

- подключается к **новой** базе;
- требует таблицы `settings`, `users`;
- если база другая, требует хотя бы одного администратора — иначе можно
  потерять доступ;
- пишет DB-настройки в целевую базу;
- обновляет `.env` с резервной копией;
- очищает кэш конфигурации;
- просит `CycleManager::requestReload()`.

Пустую базу админка не импортирует: для первой установки остаётся
`/install.php`. Это защищает от случайного создания схемы поверх чужих данных.

После `requestReload()` `cycle.php` останавливает циклы и завершается; systemd
(`Restart=always`) поднимает его заново уже с новыми credentials. Если systemd
не настроен, основной цикл нужно запустить вручную — страница предупредит.

## 3. Перезапуск циклов после сохранения

Любое сохранение раздела (нового или legacy) вызывает
`CycleManager::restartAll()`:

- циклы в состоянии `running` получают новое `generation` и перезапускаются;
- `stopped` и `disabled` не включаются;
- дочерние процессы перечитывают `.env` при старте.

Если изменилась БД, вместо `restartAll()` выполняется полный reload
супервизора. Подробно — `docs/agents/cycles.md`.

## 4. Секреты

- `DB_PASSWORD`, `REDIS_PASSWORD`, `WEBSOCKETS_AUTH_TOKEN`,
  `WEBSOCKETS_TLS_PEM_PASSPHRASE` и старый `SYSTEM_WEBSOCKETS_TOKEN` не
  выводятся в HTML.
- Поле показывается пустым с подсказкой «сохранён».
- Пустое поле = «оставить как есть».
- Для очистки — отдельная галочка «Очистить сохранённое значение».

## 5. Зависимости полей

`depends` из `InstallSchema` сохраняется. Поля Redis/WebSockets/TLS скрыты,
пока не включён их родительский переключатель. Это делает страницу короче и
не даёт сохранить бессмысленную комбинацию.

## 6. Сброс раздела

- «Сбросить раздел» возвращает значения по умолчанию.
- Для «Базы данных» кнопка скрыта: сброс на `localhost`/пустое имя ломает
  рабочую установку.
- Обязательные поля без разумного дефолта (`BASE_URL`, имя системы) при сбросе
  сохраняют текущее значение.

## 7. Проверка

```bash
php -l lib/core/Settings/*.php
php tests/settings_cycles_smoke.php
```

Вручную:

1. `/panel/settings.html` — разделы открываются, поиск фильтрует карточки,
   зависимости скрывают лишние поля.
2. Сохранить «Основные» — сообщение «Изменения сохранены», значение осталось.
3. Сохранить «База данных» с теми же доступами — ошибок нет.
4. Указать заведомо неверный пароль — ошибка подключения, `.env` не изменён.
5. Проверить, что после сохранения running-циклы перезапустились, а disabled —
   нет.
