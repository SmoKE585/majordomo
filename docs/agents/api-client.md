# Подключение агента

Эта инструкция — для агента, **использующего** HTTP API работающей системы.
Внутреннее устройство описано отдельно в [api.md](api.md).

1. Получите от пользователя адрес системы и, для внешнего доступа, токен.
   Не считывайте секреты из файлов сервера. В локальной сети токен не требуется.
2. Прочитайте `GET /api/v1/openapi.json` на этом же адресе. Это действующая
   машиночитаемая спецификация. Локальный путь из `servers[].url` добавляется
   к origin системы; сохраните префикс каталога, если система не в корне сайта.
3. Выберите операцию по `paths`, HTTP-методу и описанию. Не выводите HTTP-метод
   из имени функции и не переносите поведение старых `/api/*` на v1.
4. Подставляйте каждый path-параметр после URL-кодирования его значения.
   Например, сценарий `Вечерний свет` кодируется как `Вечерний%20свет`
   (не-ASCII символы также кодируются клиентом). Токен в URL не включайте.
5. Тела POST/PUT/PATCH — JSON-объекты с `Content-Type: application/json`.
   При отсутствии параметров отправляйте `{}`, а не пустую строку или `[]`.
   Проверяйте обязательные поля и типы по схеме; не добавляйте неизвестные поля
   к строгим операциям ядра.
6. Учитывайте HTTP-статус и `ok`. Значения `data=false`, `data=0`, `data=""`
   и `data=null` при `ok=true` являются допустимыми результатами, а не ошибками.
   Исключение — `/openapi.json`: он возвращает сам документ без оболочки `ok/data`.

## Авторизация и границы доверия

Передавайте `Authorization: Bearer <token>` либо `X-API-Key: <token>`.
Второй заголовок удобен, если перед сервером стоит отдельная HTTP Basic Auth.
Не публикуйте секрет в ответе пользователю, логах, URL, артефакте запроса.
Токен даёт доступ ко всему API; scopes и OAuth-flow отсутствуют.

Локальность решает сервер по адресу клиента, HOME_NETWORK и TRUSTED_PROXIES.
Не пытайтесь включать её через `internal=1`, `no_session`, Host,
X-Forwarded-For или другой заголовок. Не подделывайте proxy-заголовки.
Отсутствие токена допустимо только если сервер уже разрешает такой источник.
Неверный явно переданный токен даёт 401 даже в локальной сети.

## Выбор операции

| Задача | Метод и путь после `/api/v1` | Вход и полезный результат |
| --- | --- | --- |
| Список объектов | `GET /objects` | `data` — массив объектов системы. |
| Объекты класса | `GET /objects/{class}` | Имя класса в пути; записи содержат значения свойств класса. |
| Одно свойство | `GET /data/{target}` | `target=Объект.Свойство`; `data` — значение, включая null/false/0. |
| Все свойства объекта | `GET /data/{target}` | `target=ИмяОбъекта`; `data` — словарь `свойство → значение`. |
| Пакетное чтение | `POST /data` | `{"properties":["Lamp.level","Lamp"]}`; результат — словарь полных имён свойств. 1–1000 элементов. |
| Изменение свойства | `POST /data/{target}` | `{"data":значение}`. Запись может запускать ONCHANGE, связанные модули и устройства. |
| История | `GET /history/{property}` | Полное имя свойства. Query `period` и необязательный `aggregate`. |
| Выполнение метода | `POST /method/{target}` | `target=Объект.Метод`; JSON-объект с аргументами передаётся как `$params`. Результат определяет метод. |
| Сценарий | `POST /script/{script}` | ID либо точное название сценария в пути; JSON-объект аргументов. Результат определяет сценарий. |
| Событие | `POST /events/{event}` | JSON-объект параметров; результат содержит `event_id`, `event_name`, `params`. |
| Помещения | `GET /rooms`, `GET /rooms/{id}` | Список либо одно помещение: id, title, priority, object, roomIcon. |
| Новое помещение | `POST /rooms` | Обязательный `title`, необязательные `priority` и `roomIcon`; возвращает помещение. |
| Обновление помещения | `PUT /rooms/{id}` | Обязательный `title`; необязательные поля сохраняют прежние значения, если отсутствуют. |
| Порядок помещений | `POST /rooms/order` | `{"rooms":[{"id":1,"priority":20}]}`; ID и priority — целые числа. Список 1–1000 элементов, без повторных ID. |
| Удаление помещения | `DELETE /rooms/{id}` | Тело не нужно. Удаляет помещение и сбрасывает LOCATION_ID связанных объектов. |
| Чтение сообщений | `GET /messages` | Query `limit` от 1 до 1000, по умолчанию 50. `data.messages` и `data.user`. |
| Сообщение | `POST /messages` | `{"message":"Текст"}`; от 1 до 10000 символов. Отправляет через системный say(). |
| API дополнения | `/module/{module}` | Методы и поля определяет дополнение; ядро сохраняет его обработчик api($params). Дополнительный путь доступен в params.request. |
| Обработчик свойства дополнения | `POST /modulePropertySet/{module}` | Обязательны `object`, `property`, `value`; прямой вызов propertySetHandle. Обычно предпочтительнее изменение свойства через /data. |

Не считайте наличие объекта/свойства/метода с примерным именем гарантированным.
Сначала прочитайте список объектов и свойства выбранного объекта, затем выберите
точную цель. Если в API дополнения схема результата неизвестна, прочитайте
документацию этого дополнения или запросите её у пользователя; не выдумывайте поля.

`period`: положительное число часов либо day/7day/week/2week/month/year.
Значение по умолчанию — day, максимум — 10 лет. `aggregate`: max/min/count/sum/avg.
Без aggregate возвращается история, с aggregate — результат соответствующей
функции агрегации. Результат пользовательского метода, сценария или дополнения
может иметь произвольную JSON-форму: универсальной доменной схемы для него нет.

## Пример чтения и записи

Имена Lamp и level ниже — примеры, сначала найдите реальные имена в системе.

```http
GET /api/v1/data/Lamp.level HTTP/1.1
Host: YOUR_HOST
Authorization: Bearer YOUR_TOKEN
Accept: application/json
```

```json
{"ok":true,"data":0,"meta":{"request_id":"6e852085adca47e8ab1b6abbf7c576a1","timestamp":1792674000,"duration_ms":2.4}}
```

```http
POST /api/v1/data/Lamp.level HTTP/1.1
Host: YOUR_HOST
Authorization: Bearer YOUR_TOKEN
Content-Type: application/json

{"data":50}
```

Успешная запись возвращает `ok=true`, а `data` — пустой объект.
Не принимайте это за подтверждение физического состояния устройства:
связанные модули и драйверы могут выполнять действие позже. Для проверки
прочитайте соответствующее свойство, учитывая задержку интеграции.

## Ошибки и повторные запросы

При ошибке читайте `error.code`, `error.message`, `error.details.field`,
если поле присутствует. Для диагностики сохраняйте request_id, не секрет.

```json
{"ok":false,"error":{"code":"validation_failed","message":"Обязательное поле.","details":{"field":"body.data"}},"meta":{"request_id":"6e852085adca47e8ab1b6abbf7c576a1","timestamp":1792674000,"duration_ms":0.8}}
```

| HTTP / код | Действие агента |
| --- | --- |
| 400 invalid_json/invalid_path | Исправить JSON или кодирование пути. Не повторять прежний запрос. |
| 401 token_required/invalid_token | Запросить корректный токен у пользователя. Не пытаться обойти проверку сетями или заголовками. |
| 403 cross_origin_denied | Не пытаться включить произвольный CORS; использовать разрешённый серверный клиент. |
| 404 not_found | Проверить маршрут по OpenAPI и точное имя/ID по списку сущностей. Не создавать сущность автоматически. |
| 405 method_not_allowed | Прочитать Allow и исправить HTTP-метод согласно спецификации. |
| 410 gone | Функционал удалён; прекратить повторы. |
| 413 payload_too_large | Уменьшить тело до 1 МиБ, пакет разбить на части в пределах лимита элементов. |
| 415 unsupported_media_type | Отправить application/json и JSON-объект вместо form-data. |
| 422 validation_failed | Исправить поле из details.field, тип или обязательный параметр. |
| 500 internal_error | Не повторять изменяющую операцию автоматически. Сообщить request_id администратору. |
| 503 install_required | Систему должен настроить администратор через install_url. Агент не выполняет установку. |
| 503 unavailable | Исполнение прервано. Учитывать Retry-After, но действие могло уже частично выполниться. |

Чтения ядра можно повторять после временного сетевого сбоя с ограниченным
backoff. Автоматически повторять методы, сценарии, создание/удаление помещений,
сообщения, события и API дополнений нельзя: идемпотентные ключи не реализованы.
Даже GET произвольного дополнения может менять состояние. Запись свойства
может повторно вызвать обработчики, поэтому после потери ответа сначала
проверьте состояние. Успешный ответ HTTP не отменяет доменные ошибки, которые
сам пользовательский обработчик решил вернуть внутри data.

Лимит nginx также возвращает 413 с тем же error.code; у такого ответа meta
содержит request_id и generated_by=nginx, без timestamp/duration_ms приложения.
Ошибки инфраструктуры до PHP могут иметь другой формат. Не пытайтесь
интерпретировать HTML-страницу reverse proxy как JSON API.
