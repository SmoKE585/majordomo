# Журналы системы

В X-Ray откройте `errors.log` за нужную дату: сюда поступают PHP-ошибки,
предупреждения, исключения, зарегистрированные системные ошибки и сообщения
о сбоях ядра, циклов и штатных модулей. Запись содержит уровень и источник,
например `[ERROR] [core_runtime]` или `[WARNING] [php_warnings]`.

`DebMes('Сообщение')` по-прежнему пишет в `debug.log`. Обычные сообщения
служебных каналов (`threads`, `reinstall`, `maintenance` и других) остаются
в собственных журналах.

Для сообщения об ошибке из своего модуля укажите источник и уровень:

```php
DebMes('Не удалось обработать данные', 'my_module', 'error');
DebMes('Повторная попытка подключения', 'my_module', 'warning');
```

Оба сообщения попадут только в `errors.log`. Старые каналы с отдельным словом
`error`, `errors`, `warning`, `warnings`, `exception` или `exceptions`
(например `mqtt_error`, `geturl_error`, `php_exceptions`) автоматически
направляются туда же. Произвольный текст `DebMes()` не анализируется: сторонние
модули должны явно указывать уровень либо вызывать `registerError()`.

По умолчанию журналы хранятся в `cms/debmes/ГГГГ-ММ-ДД/`. Сохраняются настройки
каталога, максимального размера, отключения `DebMes` и удаления старых файлов.
PHP-диагностика учитывает `error_reporting()` и подавление через `@`;
`LOG_PHP_WARNINGS` больше не требуется. Повторного вывода предупреждений
при завершении PHP нет.

Существующие журналы не переносятся и не удаляются этой настройкой:
объединяются новые записи. Уже работающие циклы используют новый код
после своего перезапуска.
