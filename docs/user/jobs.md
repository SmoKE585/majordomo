# Задания и таймеры

Откройте `/panel/jobs.html`: здесь видны таймеры из методов и сценариев,
время запуска, попытки и ошибки. Можно отфильтровать список, создать задание
или отменить ожидающее. Кнопка с маршрутом открывает «Цепочку изменений»:
кто поставил задание, как оно выполнялось и какие изменения вызвало.

При ошибке по умолчанию предусмотрены три попытки всего. Первая повторная
попытка — через 5 секунд, вторая — ещё через 10 секунд после следующей ошибки.
Чтобы обработчик передал отказ, используйте `return cm('Lamp.turnOn');`.
Исключение, `return false;` или обрыв процесса не считаются успехом.
Постановка команды в MQTT сама по себе не подтверждает ответ устройства.
После обрыва может повториться часть команды, выполненная до сбоя.

При доступном Redis планировщик получает сроки из него без SQL-запроса
на каждом тике. Команды сохраняются в SQL; при потере Redis расписание
восстанавливается. Передача новой команды происходит после COMMIT,
незавершённые передачи сверяются раз в 30 секунд.

Повторное создание задания с прежним названием заменяет его.
Отмена не останавливает PHP-команду, которая уже начала выполняться.
Старые задания получают цепочку при первом выполнении после обновления.

Из терминала: `php majordomo jobs:list --status=failed --json`.
Техническая документация модуля — `modules/jobs/docs/jobs.md`.
