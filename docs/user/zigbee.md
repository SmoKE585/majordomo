# Zigbee устройства

`zigbee` — модуль стандартной поставки для Zigbee2MQTT. Открывается в меню
«Устройства → Zigbee устройства» или по адресу `/panel/zigbee.html`.
Старый `zigbeedev` и его таблицы не изменяются. Импорт старых привязок — отдельный этап.

## Подключение

1. Настройте общий брокер в разделе MQTT и запустите цикл MQTT.
2. На вкладке «Экземпляры» добавьте название и корневой топик без `/#`,
   например `zigbee2mqtt` и `zigbee2mqtt-garage`.
3. После сохранения MQTT перезапустит подписки. Дождитесь retained-сообщения
   `bridge/devices` или первого сообщения устройства.

Все экземпляры используют соединение, авторизацию и TLS модуля MQTT.
Отдельного MQTT-клиента или цикла Zigbee нет. Корни не должны пересекаться.
Имена топиков чувствительны к регистру. Устройство определяется экземпляром
и IEEE-адресом, поэтому переименование в Zigbee2MQTT сохраняет привязки.
Корень существующего экземпляра неизменяем: для другого корня создайте новый.

## Привязки и события

Откройте устройство, затем его свойство. Выберите объект и свойство MajorDoMo.
При необходимости задайте дополнительный метод.

Порядок: исходное сообщение → преобразование → запись свойства объекта →
его `ONCHANGE` → дополнительный метод. Не задавайте один и тот же обработчик
одновременно в `ONCHANGE` и дополнительном методе, если не нужен двойной вызов.

По умолчанию обрабатывается **каждое сообщение**, включая повторную `1`.
Для движения и кнопок это позволяет повторно включать свет и продлевать таймер.
Режим «Только изменение» сравнивает преобразованное значение с последним
успешно обработанным. Ошибка не помечает значение как обработанное.

Дополнительный метод получает `VALUE`, `NEW_VALUE`, `OLD_VALUE`, `RAW_VALUE`,
`TITLE`, `SOURCE`, `IEEE_ADDRESS`, `BRIDGE_ID`. В `ONCHANGE` остаётся обычный
контракт MajorDoMo: `NEW_VALUE`, `OLD_VALUE`, `PROPERTY`, `SOURCE`.

## Преобразования

Приём и отправка настраиваются независимо:

- **Без изменений** — значение и регистр сохраняются.
- **ON/OFF, true/false ↔ 1/0** — приём даёт числа, отправка даёт строки `ON`/`OFF`.
- **По exposes** — использует `value_on` и `value_off` описания конкретного
  устройства. На отправке сохраняет исходный тип, в том числе JSON boolean.
- **Своя таблица замен** — произвольные пары, с учётом регистра или без него.
  Значение вне таблицы передаётся без изменений.
- **Число** — умножение, прибавление и необязательное округление до 0–8 знаков.
- **Инверсия** — `1` меняется на `0`, `0` на `1`.

В таблице замен `1` — число, `true` — логическое значение, `"1"` — строка,
`""` — пустая строка, `null` — JSON null. Нулевое значение не считается пустым.
Кнопка «Проверить» выполняет преобразование без сохранения и отправки команды.

Исходное значение и результат показываются отдельно. Ошибки преобразований
видны в свойстве и в журнале; произвольный PHP-код не выполняется.

## Управление

Разрешение чтения/записи, диапазоны чисел и варианты значений определяются
из `exposes`. Для обратной синхронизации включите «Отправлять изменения
свойства объекта обратно устройству». Входящее сообщение не отправляется
обратно само себе. Вложенные свойства, например `color.x`, сохраняют JSON-структуру.

Команда ставится в общую очередь MQTT. Успех отправки не подменяет
подтверждение устройства: фактическое значение обновится с его сообщением.
На вкладке «Экземпляры» доступны разрешение подключения, переименование,
удаление из сети, настройка, повторное интервью, параметры устройства,
проверка состояния и запрос карты сети. Это реальные команды Zigbee2MQTT;
их ответы отображаются в журнале. Для каждой команды задаются свои JSON-параметры.

## Диагностика

Проверьте цикл MQTT, состояние экземпляра, исходное значение свойства,
преобразованное значение, привязку и журнал. Для экземпляра хранится до 1000
последних событий; на экране выводятся последние 100. Не создавайте одинаковые
привязки параллельно в MQTT, `zigbeedev` и `zigbee`: это независимые обработчики.

При временной ошибке очередь повторяет обработку. Доставка имеет семантику
«не менее одного раза»: обработчик, уже совершивший действие перед ошибкой,
может выполниться повторно. После исчерпания попыток ошибка сохраняется
стандартным worker в `operations_failed` и журнале `core_runtime`.

Протокол: [топики Zigbee2MQTT](https://www.zigbee2mqtt.io/guide/usage/mqtt_topics_and_messages.html),
[описания exposes](https://www.zigbee2mqtt.io/guide/usage/exposes.html).
