# Zigbee устройства

**Коротко:** модуль `zigbee` подключается к тому же брокеру, что и MQTT, и сам находит устройства Zigbee2MQTT. Вы добавляете нужные устройства, привязываете их свойства к объектам MajorDoMo и при желании назначаете комнату. Отдельный MQTT-клиент или цикл для Zigbee не нужен.

`zigbee` — модуль стандартной поставки для Zigbee2MQTT. Открывается в меню
«Устройства → Zigbee устройства» или по адресу `/panel/zigbee.html`.
Старый `zigbeedev` и его таблицы не изменяются. Импорт старых привязок — отдельный этап.

## Подключение

1. Настройте общий брокер в разделе MQTT и запустите цикл MQTT.
2. На вкладке «Экземпляры» добавьте название и корневой топик без `/#`,
   например `zigbee2mqtt` и `zigbee2mqtt-garage`.
3. После сохранения MQTT перезапустит подписки. Дождитесь retained-сообщения
   `bridge/devices` или первого сообщения устройства.

Все экземпляры используют соединение, авторизацию и TLS модуля MQTT.
Отдельного MQTT-клиента или цикла Zigbee нет. Корни не должны пересекаться.
Имена топиков чувствительны к регистру. Устройство определяется экземпляром
и IEEE-адресом, поэтому переименование в Zigbee2MQTT сохраняет привязки.
Корень существующего экземпляра неизменяем: для другого корня создайте новый.

## Привязки и события

Устройства не нужно вводить вручную. Раздел **Обнаруженные** собирает их из
`bridge/devices` и первых сообщений в настроенных корневых топиках MQTT.
Можно добавить устройство одной кнопкой, отметить несколько строк или добавить
все найденные с учётом поиска и фильтра. При добавлении можно сразу выбрать комнату.
До добавления сохраняются только данные для просмотра: обработчики и команды
устройства не выполняются. Добавление не воспроизводит старые показания.
После обновления уже использовавшиеся устройства сохраняют своё состояние.

Откройте устройство, затем его свойство. Выберите объект и свойство MajorDoMo.
При необходимости задайте дополнительный метод.

Порядок: исходное сообщение → преобразование → запись свойства объекта →
его `ONCHANGE` → дополнительный метод. Не задавайте один и тот же обработчик
одновременно в `ONCHANGE` и дополнительном методе, если не нужен двойной вызов.

По умолчанию обрабатывается **каждое сообщение**, включая повторную `1`.
Для движения и кнопок это позволяет повторно включать свет и продлевать таймер.
Режим «Только изменение» сравнивает преобразованное значение с последним
успешно обработанным. Ошибка не помечает значение как обработанное.

Дополнительный метод получает `VALUE`, `NEW_VALUE`, `OLD_VALUE`, `RAW_VALUE`,
`TITLE`, `SOURCE`, `IEEE_ADDRESS`, `BRIDGE_ID`. В `ONCHANGE` остаётся обычный
контракт MajorDoMo: `NEW_VALUE`, `OLD_VALUE`, `PROPERTY`, `SOURCE`.

Для кнопок сохраняется обычное свойство `action` и отдельное событие по виду
нажатия, например `action:single`. Значение события — время приёма с микросекундами:
повторное такое же нажатие меняет значение и может запускать `ONCHANGE`.
Привязка `action:single` не срабатывает на `double` или очистку `action`.

## Комната и её логика

В карточке устройства выберите помещение из модуля «Расположение».
При назначении создаётся обычный room-объект и пустой метод класса
`Rooms.deviceChanged`, если их ещё нет. Существующий код метода сохраняется.
Ссылка **Логика комнаты** открывает редактор обработчика именно этого помещения.

После записи привязки и дополнительного метода комнаты получают вызов
`deviceChanged` для **каждого свойства каждого сообщения**, включая повторы.
Отдельная привязка к свойству объекта для этого не нужна. Фильтр «Только изменение»
у привязки не подавляет уведомления комнаты. Свойство `action` и событие
`action:single` — разные уведомления; выбирайте нужное по `PROPERTY`.

Параметры: `DEVICE_ID`, `DEVICE_NAME`, `DEVICE_TITLE`, `IEEE_ADDRESS`, `BRIDGE_ID`,
`BASE_TOPIC`, `LOCATION_ID`, `TOPIC`, `PROPERTY` (также `TITLE`), `VALUE`,
`NEW_VALUE`, `OLD_VALUE`, `RAW_VALUE`, `SOURCE`. Значения уже преобразованы
сохранённым входящим правилом свойства; исходное доступно в `RAW_VALUE`.
При отсутствии комнаты уведомлений нет. Ошибки обработчика видны в журнале
и повторяются общей очередью; учитывайте возможность повторного исполнения.

## Перенос из zigbeedev

В обновлённой системе откройте страницу Zigbee для установки таблиц, отключите
автозапуск и остановите старый `cycle_zigbeedev`, затем выполните из каталога MajorDoMo:

```sh
mysql -u root -p ИМЯ_БАЗЫ < tools/sql/import_zigbeedev_bindings.sql
```

SQL читает старые `zigbeedevices` и `zigbeeproperties` в выбранной базе.
Старые таблицы сохраняются. Переносятся только устройства с привязками,
объекты, свойства, методы, режим обратной записи и таблицы бинарных замен.
Устройства сразу считаются добавленными. Старые показания и обработчики
во время переноса не воспроизводятся. Комнаты выбираются отдельно.
Регистрация свойств переключается с подписчика `zigbeedev` на `zigbee`,
остальные подписчики сохраняются. Совпадающие новые привязки не перезаписываются;
конфликт откатывает весь перенос. Повторный запуск не создаёт дубли.

В старом модуле `TITLE` — только его собственное название для списка, а в MQTT
устройство адресуется IEEE-адресом: топики выглядят как
`Zigbee7550/0x00158D000237212E`. Поэтому перенос ставит `FRIENDLY_NAME` равным
IEEE-адресу в том же регистре, в каком его пишет Zigbee2MQTT, а старое название
сохраняет в `TITLE`. `FULL_PATH` используется только для корневого топика: после
переименования устройства он в старой таблице устаревает.
Повторный запуск приводит имена уже перенесённых устройств к этому виду, не
создавая дублей; устройства, которые уже видел discovery, не переименовываются.
Пока метаданные ещё
не получены, разрешение записи для перенесённого свойства берётся из старой
настройки `READ_ONLY` и наличия привязки к свойству объекта. Уже полученные
`exposes` сохраняются; последующий discovery заменяет временное описание
фактическими возможностями устройства. После переноса перезапустите цикл MQTT.

## Преобразования

Приём и отправка настраиваются независимо:

- **Без изменений** — значение и регистр сохраняются.
- **ON/OFF, true/false ↔ 1/0** — приём даёт числа, отправка даёт строки `ON`/`OFF`.
- **По exposes** — использует `value_on` и `value_off` описания конкретного
  устройства. На отправке сохраняет исходный тип, в том числе JSON boolean.
- **Своя таблица замен** — произвольные пары, с учётом регистра или без него.
  Значение вне таблицы передаётся без изменений.
- **Число** — умножение, прибавление и необязательное округление до 0–8 знаков.
- **Инверсия** — `1` меняется на `0`, `0` на `1`.

В таблице замен `1` — число, `true` — логическое значение, `"1"` — строка,
`""` — пустая строка, `null` — JSON null. Нулевое значение не считается пустым.
Кнопка «Проверить» выполняет преобразование без сохранения и отправки команды.

Исходное значение и результат показываются отдельно. Ошибки преобразований
видны в свойстве и в журнале; произвольный PHP-код не выполняется.

## Управление

Разрешение чтения/записи, диапазоны чисел и варианты значений определяются
из `exposes`. Для обратной синхронизации включите «Отправлять изменения
свойства объекта обратно устройству». Входящее сообщение не отправляется
обратно само себе. Вложенные свойства, например `color.x`, сохраняют JSON-структуру.

Команда ставится в общую очередь MQTT. Успех отправки не подменяет
подтверждение устройства: фактическое значение обновится с его сообщением.
На вкладке «Экземпляры» доступны разрешение подключения, переименование,
удаление из сети, настройка, повторное интервью, параметры устройства,
проверка состояния и запрос карты сети. Это реальные команды Zigbee2MQTT;
их ответы отображаются в журнале. Для каждой команды задаются свои JSON-параметры.

## Мониторинг

Вкладка **«Мониторинг»** следит за брокером MQTT, экземплярами Zigbee2MQTT и
батареями добавленных устройств. Настройте пороги «низкий» и «критический»,
задержку пропажи связи, таймауты для устройств от сети и от батарей, а также
источник заряда: готовый процент, напряжение или отключённый контроль. Для
событий «нет связи», «связь восстановлена», «низкий заряд», «критический заряд»
и «заряд восстановлен» можно включить уведомление через `say()`, задать уровень,
интервал повтора и собственный PHP-обработчик. Настройки действуют для всех
устройств, но у отдельного устройства можно задать своё переопределение.

Оценка заряда по напряжению — приблизительная: выберите профиль батареи или
задайте свою таблицу «напряжение → процент». Если брокер или цикл MQTT недоступен,
уведомления по устройствам подавляются, чтобы не присылать лавину сообщений.

## Диагностика

Проверьте цикл MQTT, состояние экземпляра, исходное значение свойства,
преобразованное значение, привязку и журнал. Для экземпляра хранится до 1000
последних событий; на экране выводятся последние 100. Не создавайте одинаковые
привязки параллельно в MQTT, `zigbeedev` и `zigbee`: это независимые обработчики.

При временной ошибке очередь повторяет обработку. Доставка имеет семантику
«не менее одного раза»: обработчик, уже совершивший действие перед ошибкой,
может выполниться повторно. После исчерпания попыток ошибка сохраняется
стандартным worker в `operations_failed` и журнале `core_runtime`.

Протокол: [топики Zigbee2MQTT](https://www.zigbee2mqtt.io/guide/usage/mqtt_topics_and_messages.html),
[описания exposes](https://www.zigbee2mqtt.io/guide/usage/exposes.html).
