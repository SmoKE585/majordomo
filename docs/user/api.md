# API ядра

**Коротко:** API v1 работает по адресу `/api/v1/`; в локальной сети токен не нужен, снаружи — нужен `Authorization: Bearer` или `X-API-Key`. Токены выпускаются в разделе **API** панели, полный секрет показывается только один раз. Старые `/api/*` продолжают работать, но новые интеграции лучше писать на v1.

Инструкция для подключаемых ИИ-агентов: [API client guide](../agents/api-client.md).

Те же API-токены подходят для [WebSocket с живыми значениями](websockets.md).
Для веб-интерфейсов есть [вход пользователей](#вход-пользователя): постоянный
ключ вручную выпускать не нужно, логин и пароль MajorDoMo дают временный токен.
В локальной сети WS работает без ключа; после подключения отдаёт полный снимок
и дальнейшие изменения. WebSocket поддерживает только чтение.

Раздел **API** находится в панели по адресу `/panel/api.html`. Вкладка
«Документация» описывает все операции: URL, HTTP-метод, параметры, JSON тела,
схему результата и пример cURL. Описание и маршрутизатор используют один каталог
операций ядра. «OpenAPI JSON» скачивает спецификацию OpenAPI 3.0.3 для импорта
в совместимые инструменты. Спецификация доступна также на `/api/v1/openapi.json`.

## Доступ

- В локальной сети токен не требуется. Сеть задаётся `HOME_NETWORK` в `.env`;
  поддерживаются IP, CIDR, IPv4-маска `192.168.1.*` и списки через запятую.
  Если настройка отсутствует, локальными считаются loopback, частные IPv4
  (`10/8`, `172.16/12`, `192.168/16`), IPv4 link-local, IPv6 ULA и link-local.
- Внешний запрос требует `Authorization: Bearer ВАШ_ТОКЕН`.
  Если reverse proxy уже использует HTTP Basic Auth, передайте токен в
  `X-API-Key: ВАШ_ТОКЕН`. Proxy Basic Auth по-прежнему настраивается отдельно.
- HTTP-токены не передаются в URL, query-параметрах или cookie. Постоянные ключи
  интеграций не привязаны к пользователю. Пользовательские токены привязаны к
  учётной записи; оба вида дают доступ ко всему публичному API без скоупов.
  Служебный `/api/v1/panel/*` принимает только cookie-сеанс администратора.
- Loopback (`127.0.0.1`, `::1`) всегда считается доверенным reverse proxy:
  схема «nginx → 127.0.0.1:80» работает без дополнительной настройки.
  `TRUSTED_PROXIES` нужен только для дополнительных прокси: укажите их точные
  адреса или CIDR. Прокси должен передавать `X-Forwarded-For`, добавляя
  реальный адрес соединения. Произвольному заголовку от клиента API не доверяет.
  Адрес прокси сам по себе не подтверждает локальность. При неизвестном
  источнике потребуется токен. Не включайте всю домашнюю сеть в доверенные прокси.
- Для v1 разрешены браузерные запросы с домена и поддоменов из `BASE_URL`.
  С другого origin нужен явный токен; локальная сеть и cookie доступа не дают.
  Протокол должен совпадать с `BASE_URL`, для HTTPS используйте HTTPS и в интерфейсе.
  Cookie через CORS не разрешены. Без `BASE_URL` доступен только собственный origin.
  Посторонние сайты и междоменные обращения к legacy API запрещены.
  Программные интеграции без браузера работают как обычно.

## Вход пользователя

Войти может любой пользователь из раздела «Пользователи» с установленным
паролем, включая пользователя без прав администратора. Это вход во внешний
интерфейс и публичный API: cookie админки он не создаёт. Права на отдельные
объекты и команды публичного API здесь не разграничиваются; `is_admin` сообщает
роль, а `linked_object` — привязку профиля, не ограничение области доступа.

| Метод | Путь | Результат в `data` |
| --- | --- | --- |
| POST | `/api/v1/auth/login` | `access_token`, `token_type`, сроки и `user`. JSON: `username`, `password`. Предварительный ключ не нужен. |
| GET | `/api/v1/auth/me` | Текущий `user` и сроки. Требуется пользовательский токен. |
| POST | `/api/v1/auth/logout` | `logged_out: true`, текущий токен отозван. JSON: `{}`. |

```bash
curl -X POST 'https://YOUR_HOST/api/v1/auth/login' \
  -H 'Content-Type: application/json' \
  --data '{"username":"user","password":"YOUR_PASSWORD"}'
```

Пример `data` успешного входа (времена — Unix timestamp в секундах):

```json
{
  "access_token": "mdmu_...",
  "token_type": "Bearer",
  "expires_at": 1792692000,
  "absolute_expires_at": 1792731600,
  "idle_timeout": 3600,
  "user": {
    "id": 5,
    "username": "user",
    "name": "Алексей",
    "is_admin": false,
    "linked_object": "Alexey",
    "object": {"id": 42, "title": "Alexey", "class": {"id": 7, "title": "Users"}}
  }
}
```

Дальше передавайте `Authorization: Bearer mdmu_...` или `X-API-Key` во все
API-запросы. Например, `GET /api/v1/data/Alexey` возвращает свойства связанного
объекта; имя берите из `user.object.title` и кодируйте как сегмент URL.
Без привязки `linked_object` и `object` равны `null`. При удалённом объекте
`linked_object` сохраняет заданное имя, `object` равен `null`; при удалённом
классе только `object.class` равен `null`. `/auth/me` читает актуальный профиль,
но не возвращает секрет повторно. Пароль, его хеш и отпечаток не выдаются.

Токен действует час без HTTP-запросов и максимум 12 часов после входа.
HTTP-запрос с токеном продлевает срок бездействия; `expires_at` в `/auth/me`
показывает текущий ближайший предел, `absolute_expires_at` не меняется.
Выход отзывает только текущий токен; смена пароля/логина или удаление пользователя
прекращают все его сеансы. Снятие прав администратора отражается в `is_admin`
и отзывает админскую cookie, но не запрещает вход в пользовательский интерфейс.
Другие пользовательские сеансы и постоянные ключи интеграций независимы.

| HTTP / `error.code` | Действие внешнего интерфейса |
| --- | --- |
| 401 `invalid_credentials` | Показать ошибку входа без раскрытия существования логина. |
| 401 `token_expired` | Завершить собственную авторизацию и открыть вход. |
| 401 `token_revoked` | Завершить собственную авторизацию: выход или изменение учётной записи. |
| 401 `invalid_token` | Удалить неизвестный/некорректный токен и открыть вход. |
| 401 `user_token_required` | Для `/auth/me` и `/auth/logout` нужен пользовательский токен, ключ интеграции не подходит. |
| 429 `login_throttled` | Дождаться `Retry-After` в секундах. |

Для недействительного пользовательского сеанса API также возвращает
`error.details.reauthenticate: true`. В Laravel завершайте локальную сессию
при таком ответе; более короткий срок Laravel не продлевает сеанс MajorDoMo.
Три неверных входа блокируют IP на 15 минут общей с админкой защитой.
Истёкшие записи удаляются при новых входах спустя сутки после абсолютного
срока; после удаления старого токена возвращается `invalid_token`.

Для прямого браузерного клиента с поддомена используйте `credentials: 'omit'`
и явный Bearer. CORS обрабатывает OPTIONS и разрешает только `Authorization`,
`X-API-Key`, `Content-Type`. Сервер Laravel может вызывать эти же методы без
Origin и хранить токен на своей стороне; отдельный ключ системы не требуется.

Этот же `access_token` подключает WebSocket: заголовок Bearer для серверного
клиента либо `wss://YOUR_HOST/ws?token=mdmu_...` для браузера. Используйте WSS
и исключите секрет из журналов прокси. WS не продлевает срок токена фоновыми
проверками или ping. Код закрытия `1008`, причина `authorization_expired`
означают потерю доступа; завершите собственный сеанс и запросите новый вход.

Для существующей установки нужна миграция `20261026_api_user_sessions`, которая
создаёт отдельную таблицу сеансов. Штатное обновление применяет её автоматически;
после развёртывания кода перезапускается цикл WebSocket.

## Выпуск и отзыв

На вкладке «Токены» укажите название интеграции и, если нужно, дату окончания
по часовому поясу системы. Без даты токен бессрочный. Полный секрет показывается
только в ответе на выпуск: скопируйте его сразу. База хранит SHA-256-хеш,
а список показывает только префикс и состояние.

«Отозвать» немедленно запрещает использование токена извне. «Перевыпустить»
сохраняет название и срок, заменяя секрет: прежний перестаёт работать сразу.
Истёкшие и отозванные токены не восстанавливаются — создайте новый.
Локальный доступ без токена от отзыва не меняется. Если клиент всё же передал
токен, он проверяется и в локальной сети. Последнее использование обновляется
не чаще раза в минуту.

## Входящие webhook

Иногда внешнему сервису нужно вызвать PHP-обработчик установленного модуля,
например `modules/telegram/webhook.php`. Для этого не нужно открывать админку,
API или давать общий API-токен. На вкладке **«Входящие webhook»** в разделе API:

1. Укажите название, установленный модуль и PHP-файл внутри него.
2. Выберите разрешённые HTTP-методы. По умолчанию — только POST.
3. При необходимости укажите дополнительный заголовок, например
   `X-Telegram-Bot-Api-Secret-Token`. Для него будет создан отдельный секрет.
4. Создайте вход и скопируйте ссылку вида `/api/hooks/<секрет>`.
5. Вставьте её во внешний сервис. Если задан заголовок, вставьте туда и его
   дополнительный секрет.

Ссылка и секрет заголовка показываются только при создании или перевыпуске.
В базе хранятся их хеши. Передавайте ссылку только по HTTPS. «Отключить» сразу
закрывает доступ, «Перевыпустить» — сразу заменяет секрет: старая ссылка
перестаёт работать. «Секрет заголовка» перевыпускает только проверку заголовка,
не меняя ссылку. «Удалить» убирает вход без возможности восстановления.

Сервис может добавлять путь после базовой ссылки. Например, Yandex Smart Home
обращается к `/v1.0/user/devices/...`; укажите ему
`https://ВАШ_ДОМЕН/api/hooks/<секрет>` — хвост пути будет передан обработчику
как `PATH_INFO`. Для Yandex создайте вход с модулем `yandexhome`, файлом
`smarthome.php` и методами GET и POST; дополнительный заголовок оставьте пустым,
Yandex присылает свой `Authorization`. Отдельный порт и отдельный nginx-блок
для этого не нужны.

Обработчик получает исходные query-параметры, форму, файлы, тело `php://input`,
заголовки и HTTP-метод. В служебном `REQUEST_URI` секрет заменён на
`[redacted]`, чтобы журналы действий и ошибок не сохраняли полный URL. Ответ,
статус и `Content-Type` возвращаются как есть; JSON-обёртка API не добавляется.
Поэтому обработчик должен сам сформировать ответ, если он нужен внешнему сервису.

До запуска обработчика проверяются метод, дополнительный заголовок, размер тела
(до 1 МиБ) и частота обращений. Ошибки не раскрывают пути и секреты. Список
входов показывает только время последнего обращения, HTTP-статус и метод;
содержимое запросов и полные ссылки не сохраняются.

Секрет находится в URL и может попасть в access-log nginx или внешнего proxy.
Это журналы инфраструктуры: настройте в них маскирование `/api/hooks/...` или
отключите запись для этой ветки. Приложение не может изменить журналы чужого
прокси. Если reverse proxy закрывает вообще все запросы до PHP, нужно один раз
разрешить общий путь `/api/`; отдельное правило для каждого webhook не требуется.

## Формат v1

Базовый путь: `/api/v1/`. Тело POST/PUT/PATCH должно быть JSON-объектом
с `Content-Type: application/json`, даже для пустых параметров передавайте `{}`.
Максимальное тело — 1 МиБ. Пакетное чтение и перестановка помещений — до
1000 элементов. Отправка сообщений — до 10000 символов.

Успех: `{"ok":true,"data":...,"meta":{"request_id":"...","timestamp":...,"duration_ms":...}}`.
Ошибка: `{"ok":false,"error":{"code":"not_found","message":"...","details":{}},"meta":...}`.
Идентификатор запроса также находится в `X-Request-ID`.

HTTP-коды: 200 — успех; 400 — неверный JSON/путь; 401 — токен отсутствует или
недействителен; 403 — межсайтовое обращение; 404 — маршрут или сущность не
найдены; 405 — неверный метод (заголовок `Allow`); 410 — удалённый функционал;
413 — слишком большое тело; 415 — неверный Content-Type; 422 — неверные поля;
500 — ошибка исполнения/JSON-сериализации; 503 — система не установлена
или выполнение прервано. Не повторяйте автоматически команды управления:
методы, сценарии, сообщения и события могут повторно выполнить действие.

Пример сервера: `docs/deploy/nginx.conf.sample`. API имеет отдельный FastCGI
location для новых и старых URL. Он сохраняет исходный URI, передаёт заголовки
токена и оставляет JSON-ошибки приложения без подмены HTML. Превышение лимита
1 МиБ на уровне nginx тоже возвращает JSON 413; его meta содержит request_id
и generated_by=nginx, без времени выполнения PHP.

```bash
curl "https://YOUR_HOST/api/v1/data/ThisComputer.SomebodyHome" \
  -H "Authorization: Bearer YOUR_TOKEN"

curl -X POST "https://YOUR_HOST/api/v1/data/ThisComputer.SomebodyHome" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" --data '{"data":1}'
```

Есть операции чтения объектов и их свойств, пакетного чтения, изменения
свойства, истории и агрегатов, вызова метода и сценария, регистрации события,
помещений и их порядка, сообщений, API модулей и обработчиков связанных свойств.
Период истории — часы числом, `day`, `7day`, `week`, `2week`, `month`, `year`;
максимум 10 лет. Агрегат: `max`, `min`, `count`, `sum`, `avg`.

## Старые модули

Пути `/api/*` и `/api.php/*` остаются адаптером прежнего API: сохраняются
query/form-параметры, имена полей результата, `passed` и `timestamp`.
Извне теперь требуется токен; из локальной сети — нет. Для новых интеграций
используйте v1. Старые ошибки валидации/поиска остаются HTTP 400;
ошибки авторизации используют 401/403. Удалённый `/devices` отдаёт 410.

`callAPI()` и `callAPISync()` с относительным `/api/...` вызывают ядро напрямую
без HTTP и токена. Асинхронные методы и обработчики свойств сохраняют очередь;
другие фоновые действия также идут через `core_runtime`. `callAPISync()`
возвращает результат обработчика. Абсолютные HTTP-адреса в PHP-фасаде сохраняют
старое сетевое поведение и не получают привилегии внутреннего вызова.

Сторонние модули сохраняют `api($params)` и `propertySetHandle()`. Сегменты после
имени модуля находятся в `$params['request']`, query и JSON передаются в параметры.
Схема произвольного модуля определяется его автором; ядро не придумывает поля
для неизвестных модулей. PHP-обработчик должен **возвращать** сериализуемый результат,
а не печатать/завершать HTTP-ответ. Лишний вывод не попадает в JSON.

## Консоль

```bash
php majordomo api:tokens
php majordomo api:revoke 3
php majordomo api:spec
```

`api:spec` печатает чистую спецификацию; с `--json` она находится в `data`
стандартной оболочки CLI. Команда не подключается к БД. Выпуск и перевыпуск
секретов выполняются в панели, чтобы не оставлять их в терминальных журналах.
