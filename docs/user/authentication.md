# Вход в панель управления

Откройте `/panel/` и введите логин и пароль из раздела «Пользователи».
Войти могут только пользователи с правами администратора и установленным
паролем. Домашняя сеть не отменяет вход. После обновления старые сессии
завершаются — нужно войти заново.

Кнопка «Выйти» находится в верхней панели. Сессия завершается после часа
без запросов или через 12 часов после входа. Смена пароля, удаление пользователя
и снятие прав администратора прекращают доступ по существующей сессии.
Доступ админки к API работает автоматически в пределах этой сессии;
отдельный токен вручную создавать не требуется. Правила API для интеграций
и домашней сети остаются прежними.

Внешние веб-интерфейсы могут использовать логин и пароль любого пользователя,
в том числе без прав администратора: [пользовательский вход API](api.md#вход-пользователя)
выдаёт временный токен и профиль с привязанным объектом/классом. Он подходит
для HTTP API и WebSocket, а вход в админку по-прежнему требует IS_ADMIN.

После трёх ошибок за 15 минут IP блокируется на 15 минут. При необходимости
снять блокировку и посмотреть журнал можно через консоль:

```bash
php majordomo auth:unblock 192.168.1.20
php majordomo auth:reset
php majordomo logs:tail auth --lines=50
```

`auth:unblock` снимает блокировку одного адреса. `auth:reset` очищает все
счётчики и блокировки сразу — он нужен, если в журнале пустой IP: такую
блокировку командой по адресу не снять. Обе команды запускайте от того же
системного пользователя, что и PHP сайта.
При блокировке система создаёт событие `AUTH_BRUTE_FORCE`: на него можно
подписать модуль или сценарий через штатный механизм событий. В параметрах
есть IP, логин, число ошибок и время окончания блокировки. Пока IP уже
заблокирован, новые однотипные события не создаются.
Если админка стоит за дополнительным прокси, его адрес или CIDR добавьте в
TRUSTED_PROXIES: блокируется адрес клиента, а не адрес прокси. Loopback
(`127.0.0.1`, `::1`) доверенный по умолчанию — для схемы «nginx → 127.0.0.1:80»
настройка не нужна. Журнал содержит время, IP, логин и результат входа,
без паролей.

Если в журнале или событии IP пустой, сервер не получил адрес клиента: запрос
пришёл от прокси, который не передал `X-Forwarded-For`. Проверьте, что nginx
отдаёт PHP `REMOTE_ADDR` (`fastcgi_param REMOTE_ADDR $remote_addr`) и, если
перед ним есть ещё один прокси, передаёт исходный адрес
(`proxy_set_header X-Forwarded-For $remote_addr`), а адрес этого прокси указан
в TRUSTED_PROXIES. Пока адрес неизвестен, вход работает как обычно, но
автоматическая блокировка не включается: иначе одна ошибка или один планшет
с бракованным заголовком заперли бы вход всем пользователям. В `auth.log`
такие попытки отмечены как `failure_unattributed` и `success_unattributed`.

Восстановление пароля доступно только через существующую консольную команду:

```bash
php majordomo users:list
php majordomo users:password 1
```

Пароль вводится скрыто дважды. Команда меняет пароль выбранной учётной записи,
сохраняя её роль. Сброс пароля не снимает активную блокировку IP автоматически.
