# Удобный фасад Redis в ядре

Дата обсуждения: 2026-10-25. Статус: **Запланировано**.

## Цель и требования

- [ ] Добавить фасад в стиле Laravel: `Redis::get()`, `set()`, `hget()`,
  `hset()`, `incr()`. Сигнатуры и состав первой версии уточнить при реализации.
- [ ] Переиспользовать `RedisConnection`, `RedisClient` и `Config`.
  Не создавать второе независимое подключение.
- [ ] Сохранить `Core::redis()`, `mjdGetRedisConnection()` и поведение старого
  кода. Массовый перенос вызовов не требуется для первого выпуска.
- [ ] Использовать собственный namespace, предварительно
  `MajorDoMo\Core\Facades\Redis`: глобальное имя `Redis` занято расширением PHP.
- [ ] Определить правила префиксов, TTL и результатов команд. Сохранить
  изоляцию установок и восстановление соединения в долгоживущих процессах.
  Не повторять запись автоматически, если результат её выполнения неизвестен.
- [ ] При отказе Redis сохранять явные ошибки обязательных операций,
  не подменять отказ успешным ответом.
- [ ] Добавить примеры и инструкции для нового кода. Очереди и блокировки
  переносить только отдельной проверенной задачей.

## Открытые вопросы

Определить поддерживаемые команды, обработку нескольких ключей и правила
сериализации. Установка `illuminate/redis` не утверждена: сначала оценить,
достаточно ли существующих классов. Дополнительные возможности сверх
обсуждённых команд не включать в первую версию автоматически.

## Критерии готовности

- [ ] Фасад и legacy работают без изменения существующих ключей.
- [ ] Проверены типы результатов, срок жизни, префиксы, ошибки и восстановление
  подключения с mock или отдельным изолированным Redis.
- [ ] Прикладные операции не затрагивают чужие установки и служебные ключи.
