# Коллекции Laravel для работы с наборами данных

Дата обсуждения: 2026-10-25. Статус: **Запланировано**.

## Цель

Использовать коллекции для обработки наборов данных вместо ручных цепочек
операций над массивами: фильтрация, преобразование, группировка, сортировка
и получение отдельных полей. Включить доступность коллекций в первый этап
внедрения ORM; перенос существующего кода выполнять постепенно.

## Требования

- [ ] Использовать стандартные `Illuminate\Support\Collection` и `collect()`
  из `illuminate/collections`, без собственной альтернативной реализации.
  Пакет входит в зависимости `illuminate/database`; при прямом использовании
  в коде явно закрепить зависимость в Composer и согласовать версии пакетов.
- [ ] Сохранить коллекции моделей в новом коде Eloquent, не превращать
  результаты выборки в массив сразу ради дальнейшей обработки.
- [ ] В новом и изменяемом коде предпочитать коллекции для наборов данных:
  `map`, `filter`, `pluck`, `groupBy`, `keyBy`, `sortBy`, `first`, `contains`,
  `sum` и другие штатные операции по необходимости.
- [ ] Добавить инструкцию агентам и рабочие примеры вместе с внедрением ORM.
  Переводить затронутые операции, не заменять все массивы проекта механически:
  конфигурация, параметры и отдельные записи не обязаны становиться коллекциями.
- [ ] На границах legacy, шаблонов и публичных API сохранять существующие
  массивы, ключи, типы и форматы JSON. Старые `SQLSelect` и helpers не должны
  неожиданно возвращать объект коллекции вместо массива.
- [ ] Выбирать преобразование в массив осознанно: `all()` сохраняет элементы
  коллекции как есть, `toArray()` преобразует вложенные объекты с поддержкой
  такого преобразования. Для моделей отдельно проверить состав полей и формат.
- [ ] Фильтрацию и агрегирование больших выборок выполнять в БД, когда это
  уместно. Не загружать таблицу целиком только ради `filter` или `sum`.
  Для больших потоков оценить `LazyCollection` и пакетную обработку без
  накопления всего набора в памяти.

## Открытые вопросы

Версию `illuminate/collections` выбрать вместе с ORM после решения по PHP.
Повышение минимальной версии PHP по-прежнему не согласовано. Перед подключением
проверить отсутствие конфликтов глобального helper `collect` и совместимость
пакетов. Поддержка коллекций в новом прикладном кэше и формат их восстановления
требуют явного решения; не считать произвольные объекты разрешёнными автоматически.

## Критерии готовности

- [ ] После штатного обновления коллекции доступны в веб-запросах и CLI.
- [ ] Рабочие примеры покрывают преобразование, фильтрацию, группировку,
  пустые наборы и сохранение ключей и типов.
- [ ] Проверено использование коллекций моделей и явное преобразование
  на границах старого API без изменения его контрактов.
- [ ] Большие наборы обрабатываются без лишней полной загрузки в память
  и дополнительных запросов из callback коллекций.
