# Eloquent ORM в ядре без нарушения совместимости

Дата обсуждения: 2026-10-25. Статус: **Запланировано**.

## Цель

Подключить через Composer пакет `illuminate/database` для работы с моделями
и Query Builder, как в Laravel. Весь Laravel устанавливать не требуется.
Обновление должно сохранить старый код и модули, после чего запросы можно
постепенно переводить на модели при обычных изменениях проекта.

## Первый этап

- [ ] Выбрать версию пакета после решения по минимальной версии PHP.
- [ ] Подключить ORM через общий загрузчик ядра для веб-запросов и CLI,
  используя существующий `Config`, без второй системы настройки БД.
- [ ] Обеспечить доступность [коллекций Laravel](collections.md) в том же
  обновлении: в новом коде работать с коллекциями, сохраняя массивы legacy API.
- [ ] Создать базовую модель и `lib/core/Models/` для системных таблиц.
  Состав уточнить по схеме: классы, объекты, свойства и значения, методы,
  пользователи, настройки, история, задания.
- [ ] Настроить имена таблиц, ключи `ID`, типы и связи; отключить
  автоматические `created_at`/`updated_at` там, где таких полей нет.
- [ ] Сохранить `SQLSelect`, `SQLSelectOne`, `SQLExec`, `SQLInsert`,
  `SQLUpdate`, `$db`, массивы результатов, типы, передачу по ссылке и ошибки.
- [ ] Решить совместную работу транзакций: сейчас используется `mysqli`,
  Eloquent работает через PDO. Одинаковые настройки не делают соединения
  одной транзакцией. Смешанная атомарная операция должна использовать одно
  соединение либо целиком переноситься на новый слой.
- [ ] Добавить обязательную инструкцию агентам и ссылки из входных правил.
  Перенести и проверить несколько реальных операций как пример подхода.
- [ ] Проверить установку зависимости и нужных расширений PHP при штатном
  обновлении и чистой установке системы.

## Правила постепенного перехода

- При изменении операции с данными переводить затронутые запросы на модели
  или Query Builder с сохранением поведения. Не переписывать попутно весь модуль.
- Публичным API остаются helpers и `Core::*`. Модели используются внутри
  сервисов, владеющих данными. Нельзя заменить `setGlobal` сохранением модели
  и обойти кэш, `ONCHANGE`, историю, аудит, связанные модули и уведомления.
- Модели таблиц дополнений живут внутри модулей; системные модели — в ядре.
- Не переименовывать таблицы и поля ради ORM. Проверить движки таблиц:
  MyISAM и MEMORY не получают транзакции от подключения Eloquent.
- Сохранять форматы данных на границах legacy, не добавлять N+1 и загрузку
  больших журналов целиком в модели.
- Технический SQL допустим в миграциях, диагностике и специальных запросах
  с обоснованием. Модель не обязательна для каждой служебной операции.
- Старый слой не удалять до завершения перехода. Прямые обращения сторонних
  модулей к `mysqli` проверить отдельно при изменении драйвера.

## Открытые вопросы

1. Проект требует PHP 8.1, локально используется 8.4. Illuminate 10 совместим
   с 8.1, но поддержка безопасности Laravel 10 завершилась 2025-02-04.
   Illuminate 12 требует PHP 8.2+. Повышение минимума не согласовано.
   Перед внедрением повторно проверить актуальные требования и поддержку.
2. Выбрать стратегию: оставить `mysqli` для legacy на переходный период или
   перевести совместимый адаптер на единый PDO. Учесть прямые обращения
   к соединению и существующие транзакции.
3. Состав моделей и первые переносимые операции уточнить по актуальному коду.

[поддержка Laravel 10](https://laravel.com/docs/10.x/releases),
[Illuminate 12](https://github.com/illuminate/database/blob/12.x/composer.json).

## Масштаб и последующие задачи

Предварительный текстовый подсчёт на дату обсуждения: около 650 совпадений
обращений к данным в 59 файлах `lib/core/` и 730 в 90 файлах `modules/`.
Это ориентир масштаба, а не число запросов, обязательных к замене.

Первый этап оценён в несколько рабочих дней; основные сервисы — в несколько
недель; все модули — в отдельную постепенную работу на недели. Оценки требуют
уточнения после выбора версии и соединений. Полный отказ от SQL не входит
автоматически в задачу подключения ORM.

## Критерии готовности первого этапа

- [ ] После обновления модели доступны, старые модули сохраняют контракты.
- [ ] Проверены чтение, создание, изменение, удаление, взаимная видимость
  данных, ошибки и откат транзакций нового и старого слоя.
- [ ] Сохранены обработчики свойств, история, аудит, очередь, уведомления
  и обновление кэша после завершения транзакции.
- [ ] Проверки изолированы от рабочей БД и Redis. Совместимость транзакций
  MySQL/MariaDB и legacy проверена отдельно: одного SQLite недостаточно.
- [ ] Инструкции соответствуют установленной версии ORM.

Связанные задачи: [коллекции](collections.md), [Redis](redis-facade.md), [Cache](cache-facade.md).
